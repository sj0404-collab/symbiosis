# Тестовый канал обновляемого ядра

Цель: оставить лаунчер нативным и обновлять второе ARM64-ядро через доверенный канал без пересборки APK. Старый APK 273 закрепляет SHA-256 в `EngineLoader.kt`, поэтому обновления ядра без нового APK он не принимает. Eden, JNI-мост, интерфейс и встроенные библиотеки находятся внутри APK; они не будут обновляться таким каналом без отдельной архитектуры. WASM-порт не создан; существующий Android `.so` нельзя исполнять как WASM.

## Прототип формата

`SignedCoreManifest.kt` проверяет только подпись RSA/SHA-256, строгий формат, пределы, минимальный номер и, отдельным вызовом, размер и SHA-256 файла. `sign_core_manifest.py` подписывает метаданные с указанным оператором ключом, не создаёт ключ и ничего не публикует. Тесты проверяют подмену, другой ключ, неправильный формат, ограничения, откат и совместимость Python/OpenSSL с Kotlin/JCA. `CoreUpdateStore.kt` — отдельный прототип установки во временную папку, сверки подписи/хеша/базового ELF ARM64, блокировки сеанса, атомарного переименования и выбора последней проверенной версии. Host-тесты проверяют обрыв, неправильный хеш, архитектуру, занятый сеанс, повтор/откат и повреждение файла; это не проверка Android или внезапной потери питания. В текущей ветке канал подключён к загрузчику только при `BuildConfig.DEBUG`, добавлены нативные кнопки обновления и копирования журналов. Публичный ключ закреплён в приложении; закрытый создан отдельно и хранится в секрете GitHub Actions. APK 274 включает эту интеграцию; подписанный манифест опубликован на Pages. Синтетическая проверка в ARM Redroid прошла; физический телефон и UI-кнопки не проверены.

Пятистрочный ASCII-формат с LF, включая завершающий LF:

```text
SYMBIOSIS-KENJI-1
sequence=1
bytes=57321040
sha256=<64 lowercase hex digits>
signature=<base64 RSA signature>
```

Подписаны первые четыре строки, включая завершающий LF. Путь к файлу выводится только из проверенных номера и хеша, сам манифест не может указать произвольный URL. Пример: `https://github.com/sj0404-collab/symbiosis/releases/download/engine-test-1/libkenji-<sha256>.so`. Pages может раздавать **подписанный манифест**, файл ядра — отдельный версионированный release asset. Канал по замыслу тестовый; неизменность тэга/asset GitHub сама по себе не является защитой, фактический файл проверяется по подписанному хешу.

## Остающиеся ограничения и проверки

* Соответствие публичного ключа закрытому секрету проверено при публикации версии 1; секрет не хранится в git, Pages, APK или журналах. Автоматическая смена ключа не реализована: потеря ключа потребует нового APK.
* Подключить и дополнительно проверить прототип установки; ограничить соединения, проверить 16K ELF и совместимость моста. Протестировать файловую систему Android, аварийный выход и восстановление после потери питания.
* Проверить фактическую межпроцессную блокировку установки с игрой и проверкой ядра; не менять файл под загруженным процессом. Проверить поведение при повторном `dlopen`, при ошибках, нехватке места и потере сети.
* Версии считать только по проверенной подписи и сохранять максимальную принятую версию с проверкой целостности, не обещая абсолютной защиты от отката после очистки данных приложения. Ручной откат — только в явно определённом, безопасном режиме.
* Проверить нативные кнопки, статус и инструкцию на Android. Подпись/скачивание не доказывают работоспособность игры. Локальный журнал событий обновления содержит номер и хеш ядра; журнал ядра может содержать пути и сведения устройства. Автоматическая публикация/отправка пользовательских логов не предусмотрена.
* Workflow публикации, отдельный тестовый asset и реально обслуживаемый Pages-манифест версии 1 проверены. При следующих обновлениях проверять новые ядра и повторять Android-сценарии, включая отключение сети, повторный запуск и падения.

Сборка 273 не даёт такого обновления без APK; функция впервые опубликована в тестовой сборке 274. Известные SSL-заглушки и падение Account без PID не исправляются подписыванием.
