# Symbiosis: инструкция пользования

Тот же текст есть в приложении: **Руководство** (кнопка на стартовом экране, а также
«Инструменты» → «Руководство пользования»). Если инструкция и приложение когда-нибудь
разойдутся, права инструкция: она проверяется тестом на то, что каждый раздел ссылается
на существующий экран (`tests/NativeLibraryPresenterTest.kt`).

Версия текста: 2.

---

## 1. С чего начать: три шага

Порядок важен. Пока нет ключей, ни один дамп не откроется, и пустой список будет
выглядеть как «папка не та», хотя дело не в ней.

1. **Ключи и прошивка.** «Ключи» → `prod.keys`, затем файлы прошивки. Без них заголовок
   файла зашифрован: приложение видит файл, но не знает, что это за игра, и помечает его
   «нет ключей».
2. **Папка с играми.** «Папки» → «Добавить папку». Выберите папку, где лежат NSP, XCI,
   NCA или сжатые NSZ. Папок может быть несколько, вложенность читается.
3. **Нажать игру.** Вернитесь на стартовый экран: игры уже в списке. Нажатие запускает
   игру, долгое нажатие открывает её свойства — масштаб, драйвер, сейвы.

---

## 2. Экран библиотеки: что означают значки

Стартовый экран — нативная библиотека. Список показывает **все** файлы в выбранных
папках, а не только те, что запускаются. Поэтому «игр нет» больше не значит
«файлы не нашлись».

| Что видно | Что это значит |
|---|---|
| Строка сверху | Счёт по всем папкам без фильтров: `12 игр · 3 обновления · 40 сжатых → Конвертер · 2 не читаются` |
| Метка на плитке | Формат файла: `nsp`, `xci`, `nca`, `nro`. Обновления и DLC стоят рядом со своей игрой отдельными плитками |
| Пометка «сжатый» | Образ упакован (NSZ/XCZ/NCZ). Сначала распаковывается — Конвертером |
| Пометка «нет ключей» | Заголовок не расшифровался: нужны `prod.keys` и прошивка |
| Пометка «часть» | Разрезанный образ: `.nsp.00`, `.nsp.01` … нужны все части |
| Фильтры | «Все файлы» / «Запускается» / «Не запускается» |
| Поиск | Ищет по названию, Title ID и имени файла |
| Долгое нажатие | Свойства конкретной игры: настройки только для неё, сейвы, удаление |

## 3. Файл виден, но не запускается

Нажмите такую плитку — приложение скажет причину словами и предложит действие.

| Причина | Что делать |
|---|---|
| Сжатый NSZ / XCZ / NCZ | «Конвертер» → выбрать файл → подождать. Распаковка идёт на телефоне и занимает столько же места, сколько сам образ: освободите его заранее. Готовый NSP появится в папке конвертера и сразу в библиотеке |
| Часть разрезанного образа (`.nsp.00`, `.xci.01`) | Ядро открывает только целый файл. Положите все части в одну папку — библиотека склеит их в одну игру |
| Нет ключей | «Ключи» → `prod.keys`, затем прошивка. После установки нажмите «Искать игры»: заголовки расшифруются. Файлы при этом никуда не переносятся |

## 4. Где что лежит

Главное — на стартовом экране. Остальное открывается кнопками сверху и из «Инструментов».

| Экран | Что там |
|---|---|
| **Библиотека** (стартовый) | Игры, поиск, фильтры, запуск, свойства игры по долгому нажатию |
| **Папки** | Откуда берутся игры: добавить или убрать папку, посмотреть, что внутри |
| **Конвертер** | Распаковка сжатых образов; здесь же очередь и готовые NSP |
| **Ключи** | `prod.keys` и прошивка консоли |
| **Инструменты** | Подбор FPS, диагностика, движки, утилиты ROM, сейвы, лаунчеры, справочник настроек, руководство |
| **Два ядра** | Гибрид: Eden + Kenji-NX, общие и свои настройки, ядро по умолчанию |
| **Руководство** | Эта инструкция, с поиском |
| **Расширенная панель** | Старая универсальная панель: пространства, выбор ядра, тонкие переключатели. Для обычной игры не нужна |

Кнопки стартового экрана, слева направо: **Искать игры**, **Папки**, **Конвертер**,
**Ключи**, **Инструменты**, **Руководство**.

## 5. Папки с играми и конвертер

**Папки.** «Инструменты» → «Папки с играми». Кнопка «Добавить папку» — прямо здесь,
долгое нажатие на папку — «Пересканировать» или «Убрать из списка».

Две вещи, которые раньше работали неправильно и теперь исправлены:

- **Папки больше не пропадают.** Было: папка, к которой отозвали доступ (а система отзывает
  его сама, если приложение упало), удалялась из настроек при первом же обходе — навсегда,
  вместе со списком игр в ней. Стало: папка остаётся в списке и помечается «нет доступа»;
  нажатие на неё открывает выбор папки, чтобы вернуть доступ. Плюс у приложения есть вторая
  копия списка — если настройки после сбоя остались недописанными (а именно так и появляется
  «осталась одна папка из четырёх»), недостающие возвращаются из копии.
- **Вложенные папки не съедают друг друга.** Если добавить `Games` и `Games/Switch`, обе
  остаются в списке; дубликаты игр отсекаются при показе, а не удалением папок.

**Конвертер.** Даёте ему NSZ / XCZ / NCZ — получаете файл, который открывается.

Как он устроен теперь (и почему раньше не работал):

- **Формат повторяет ПК-версию.** Сжатый образ устроен так: заголовок NCA, таблица
  секций с ключом и счётчиком каждой секции, дальше либо блоки по 16 КБ и больше, либо
  один сплошной поток zstd. Секции хранятся **расшифрованными**, и на выходе шифрование
  возвращается на место (AES-128-CTR). Раньше таблица секций читалась не по тому
  смещению, а шифрование не возвращалось вовсе — поэтому «распаковка выдавала ноль» или
  давала файл, который ядро отказывалось открывать.
- **Файл XCI: раздел с игрой лежит по фиксированному смещению 0xF000.** Старая версия
  считала его из другого поля заголовка — то есть искала данные не там, и «сохранить как
  NSP» не могло работать ни на одном настоящем образе.
- **Проверено на настоящих файлах до сборки.** Тест собирает NSZ, XCZ и NCZ по тому же
  формату (отдельным скриптом, не тем кодом, который их потом читает), распаковывает их
  и сравнивает результат байт в байт — вместе с AES и настоящим zstd.
- **Причина отказа — по-русски.** Вместо «распаковка не удалась» будет «файл обрезан:
  скачивание не завершилось» или «контейнер NSP повреждён».

- Работа идёт в **уведомлении в шторке**: видно, какой файл распаковывается и сколько
  осталось, есть кнопка «Остановить». Можно уйти из приложения — распаковка не прервётся.
- Результат кладётся в **`Download/Symbiosis`** — папку видно в проводнике и по кабелю.
  Точный путь написан и в уведомлении, и в приложении. Если доступа к «Загрузкам» нет,
  приложение скажет об этом и положит файл в свою папку, а не сделает вид, что всё хорошо.
- Не забудьте разрешить уведомления, когда приложение попросит: без разрешения на Android 13+
  уведомление не показывается — и прогресс будет «невидимым».

## 6. Если игра вылетает при выходе

Приложение записывает последние шаги: запуск какой игры, остановка эмуляции, возврат
в библиотеку. Откройте «Инструменты» → «Диагностика» — вверху будет «Последние шаги перед
выходом»: время, шаги и пометка, завершилась ли прошлая сессия сбоем. Кнопка «Скопировать
отчёт» копирует это вместе с разбором.

Это нужно, чтобы не гадать: по шагам видно, падает ли ядро при запуске, при разрушении окна
или уже после возврата в библиотеку. Пришлите этот текст — по нему видно, где искать.

## 7. Второе ядро: скачать, проверить, отдать оригиналу

«Инструменты» → «Два ядра» → карточка **Kenji-NX**.

- **«Скачать (55 МБ)»** — качает один файл с релиза, проверяет контрольную сумму, делает
  файл доступным только для чтения и сразу пробует загрузить. Сообщение о ходе и итоге —
  плашкой **сверху экрана**, рядом с кнопкой.
- **«Проверить»** — запускает ядро в отдельном процессе `:kenji`. Так проверка, которая
  падает, роняет только этот процесс, а не приложение: вместо исчезновения будет фраза
  с причиной.
- Под карточкой — **«Проверено на этом устройстве»**: процессор, разрядность процесса,
  версия Android, размер страниц памяти и выравнивание скачанного ядра. Если что-то не
  подходит, там же написано, почему и что делать.

**Если ядро не подходит именно вашему телефону.** Это бывает по трём причинам, и все они
видны в этом блоке: процессор не arm64, приложение установлено 32-битным, или ядро собрано
с выравниванием 4 КБ, а телефон работает со страницами 16 КБ. На релизном ядре выравнивание
16 КБ, поэтому последний случай к нашей сборке не относится.

**Запасной путь, который работает всегда.** Если на телефоне установлен оригинальный APK
Kenji, приложение предложит «Играть через Kenji» — и на плитке игры, поставленной на второе
ядро, тоже: своё ядро не готово → игра открывается в официальном приложении, а не молча
уходит на Eden. Так вы получаете ровно то поведение, к которому привыкли в оригинале.

## 8. Плагины: починить, не пересобирая

Бывает так: игра на втором ядре вылетает, или на драйвере Mali мигает картинка, а новой
сборки ждать долго. Для этого есть плагины — **«Инструменты» → «Плагины»**.

Плагин — это файл с правилами: «если у игры такой-то признак — такая-то настройка, такое-то
ядро или такая-то пометка». **Кода он не исполняет.** Поэтому его можно взять у кого угодно и
не бояться: самое плохое, что он сделает, — выставит неверную настройку, и это видно в списке
и выключается одним нажатием.

Что уже есть:

| Плагин | Что делает | Включён? |
|---|---|---|
| `mali-safe` | На Mali отключает «быстрое время GPU» и анизотропию; предупреждает, если памяти меньше 6 ГБ | да |
| `lowram-eden` | На устройстве меньше 6 ГБ всегда запускает игры на Eden | нет |
| `template` | Не срабатывает никогда — образец, с которого можно начать свой | нет |

Свой плагин: в «Плагинах» нажмите «Скопировать путь», положите туда `.json` по образцу и
нажмите «Перечитать». Файл с тем же `id`, что у встроенного, **заменяет его** — так чинится
встроенное правило, не дожидаясь новой сборки.

Что можно в условии: `title`, `path`, `ext`, `titleId`, `gpu`, `engine`, `ramGb`. Сравнение —
шаблон со звёздочкой (`"*mali*"`) или число (`{"ramGb": {"lt": 6}}`). Несколько полей в одном
условии — «и», массив значений — «любое из».

Что можно сделать: `setting` (настройки ядра — только те, что есть на экране «Два ядра»),
`core` (запускать другое ядро), `file` (пометка на плитке), `banner` (сообщение над списком).

```json
{
  "schema": 1,
  "id": "splatoon-fix",
  "name": "Splatoon 3 на Eden",
  "priority": 200,
  "rules": [
    { "type": "core", "when": { "title": "Splatoon*" }, "core": "eden",
      "reason": "на втором ядре вылетает после заставки" }
  ]
}
```

Ошибка в файле не ломает приложение: плагин не применится, а на экране появится причина —
например «правило 1: нет настройки «memy». Есть: memory, scale, nce…». Опечатка в имени
настройки — это ошибка загрузки, а не «плагин молча ничего не делает».

## Что нового в этой сборке (3)

- **Распаковка NSZ / XCZ / NCZ переделана** по тому же формату, что у ПК-версии (SAK):
  таблица секций, блоки, сплошной поток, возврат шифрования AES-128-CTR. На выходе —
  рабочий NSP/NCA, а не «ноль байт». Проверено тестом на собранных по этому формату
  файлах, байт в байт.
- **XCI → NSP починен:** раздел с игрой ищется по фиксированному смещению 0xF000.
- **Дубликаты игр убраны.** Если добавить `Games` и `Games/Switch`, один и тот же файл
  больше не появляется двумя плитками: у него один отпечаток, независимо от того, через
  какую папку его нашли.
- **Обложки больше не съезжают.** Прошлый запрос картинки отменяется при
  переиспользовании плитки, а файлам без обложки больше не подставляется «успешная»
  заглушка — остаётся буква.
- **Появился «Журнал ядра»** — см. раздел 13. Раньше дебаг-журнала ядра не было нигде.
- **Причина отказа конвертера — по-русски:** «файл обрезан», «контейнер NSP повреждён»,
  «мало места» вместо английской строки из ядра.

## Что нового в этой сборке (2)

- **Папки с играми больше не пропадают.** После вылета оставалась одна папка из четырёх —
  это было удаление, а не сбой отображения; теперь папки восстанавливаются, а отозванный доступ
  виден как «нет доступа» с кнопкой возврата.
- **Добавить папку — с экрана папок.** Долгое нажатие убирает папку из списка (игры на диске целы).
- **Конвертер виден:** уведомление в шторке с текущим файлом и «Остановить»; результат в
  `Download/Symbiosis`; путь написан в уведомлении и в приложении.
- **Панель показывает тот же список игр, что и лаунчер.**
- **«Последние шаги перед выходом»** в «Диагностике» — чтобы сбой при выходе из игры
  перестал быть загадкой.

## Как выглядит и почему так

Экран тёмный, почти чёрный, с подсветкой сверху. Это не стиль ради стиля: игра в
эмуляторе — тёмный кадр, и светлая панель вокруг него мешает смотреть.

Цвет в приложении отвечает на вопрос «что это», а не украшает:

| Что | Цвет |
|---|---|
| **Игра** | Свой оттенок из её Title ID. Одна и та же игра всегда одного цвета, соседние — разных. Полоса слева и буква в кружке дают узнать игру раньше, чем вы прочитали название |
| **Формат файла** | `nsp` — голубой, `xci` — лаймовый, `nsz` — янтарный, `DLC` — фиолетовый |
| **Второе ядро** | Розовый. Везде: карточка Kenji-NX, точка у «своих» настроек, пометка `kenji` на плитке игры |
| **Eden** | Голубой |
| **Кнопки** | У каждой свой цвет, и тот же цвет у экрана, куда она ведёт: «Конвертер» янтарный, «Инструменты» розовые, «Руководство» синее |

Ничего не держится на одном цвете: рядом всегда есть слово. Цвет только ускоряет,
он не заменяет подпись — иначе тем, кто не различает оттенки, пришлось бы угадывать.

Текст поверх цветных плашек выбирается по яркости, а не «белый, потому что красиво»:
контраст проверяется тестом, минимум 4.2 к 1.

Сборка 41200104556 (`8e613d857ed7b3047cd16d773d1aa96b`, 42.7 МБ,
https://gofile.io/d/3cIAKSo5) — с новым оформлением и обоими ядрами. Три вещи, которые видно сразу:

## 9. Сейвы, прогресс и облако

**Сейвы игры.** Долгое нажатие на плитку → «Сейвы и прогресс». Там видно всё, что можно
измерить:

- сколько сохранений и сколько они весят;
- когда создан первый и когда было последнее;
- **сколько дней не заходили** («сегодня», «вчера», «12 дней назад»);
- **сколько времени прошло с последнего сохранения** — это ответ на «играю десять часов, а
  прогресса нет»: видно, что игра не сохранялась двенадцать часов;
- все профили отдельно, с путями.

**Процент прохождения.** Ставите вы — кнопками 0 / 10 / 25 / 50 / 75 / 90 / 100 или своим
числом. Скажу прямо: автоматически его взять неоткуда. Настоящий процент лежит внутри сейва
в формате конкретной игры; ни размера папки, ни числа файлов для этого не хватает. Я мог бы
показать «оценку», но оценка в этом месте вредна: по ней решают, начинать ли заново.

**Облако.** «Инструменты» → «Облако». Нужен **WebDAV** — он есть у Яндекс.Диска, Nextcloud,
Box, Облака Mail.ru и домашнего сервера. Выбираете сервис, вводите логин и **пароль
приложения** (не пароль от аккаунта), жмёте «Сохранить и проверить».

- **Сейвы** уходят в облако сами после выхода из игры (переключатель) и вручную — кнопками
  «Сейвы ↑ / ↓» у каждой игры. Слияние пофайловое: скачивание не затирает локальный сейв,
  который новее.
- **Образы игр** — кнопками «Образ ↑ / ↓», в `Download/Symbiosis/Games`. Автоматически они
  не заливаются: это гигабайты и трафик.
- **Чего нет:** запуска игры «прямо из облака». Эмулятору нужен локальный файл и десятки
  тысяч произвольных чтений — по сети это невозможно. Схема такая: скачать → играть →
  сохранения уходят обратно.

## 10. Два ядра: гибрид

В приложении два ядра — **Eden** (встроен) и **Kenji-NX** (~55 МБ, скачивается один раз).
Где одно падает, другое иногда едет, поэтому ядро выбирается не на всё приложение, а на игру.

- **Выбрать ядро для игры.** Долгое нажатие на плитке в библиотеке → «Запустить на Eden» или
  «Запустить на Kenji-NX». Выбор запоминается за этой игрой, а пометка «kenji» на плитке
  показывает, каким ядром она пойдёт.
- **Скачать второе ядро.** «Инструменты» → «Два ядра» → «Скачать». Игры, сейвы и ключи общие:
  скачивается только ядро, библиотеку заново собирать не нужно.
- **Как связаны настройки.** Общие строки — масштаб, режим дока, кэш шейдеров, NCE — второе
  ядро берёт у Eden, пока вы не измените их на экране «Два ядра». Свои — память, PPTC,
  macro HLE, анизотропия, интернет, проверка целостности — принадлежат только ему, и Eden их
  не перетирает. Нажатие на строку переключает значение; «Вернуть значения Eden» снимает все
  ваши переопределения.
- **Ядро по умолчанию.** Тем же экраном: с ним запускаются игры, у которых своего ядра нет.
- **Если второе ядро не скачано.** Игра всё равно запустится — на Eden, и приложение скажет,
  почему не на том ядре.

Переключение ядер больше ничего не стирает: у Eden свой конфиг, у Kenji свой, а выбор ядра для
игры — одна короткая запись.

## 11. Если медленно

На Mali-G57 с 8 ГБ помогает не «включить всё», а изменить три вещи.

- **Масштаб 0.75x.** Настройки → Графика → Разрешение. Заметная часть работы GPU уходит
  на пиксели, которых на экране телефона не видно.
- **Подбор FPS.** «Инструменты» → «Подбор FPS»: ставит настройки под это устройство,
  а не «максимум качества».
- **Диагностика.** Показывает, какие настройки доехали до драйвера, а какие Mali молча
  выбросил. «Включено, но не работает» здесь — обычное дело.

## 12. Сейвы, папка данных, перенос

- **Где сейвы.** Папка данных (по умолчанию — внутренняя память приложения) → `saves`.
  Свойства игры показывают «сейв 128 КБ», если он уже есть.
- **Сменить папку данных.** «Инструменты» → «Утилиты» → сменить папку данных, затем
  перезапустить приложение. Папку с играми это не затрагивает.
- **Перенос на другой телефон.** Скопируйте папку данных целиком: там сейвы, шейдеры и
  настройки игр. Игры можно не копировать — достаточно заново указать папку.

## 13. Журнал ядра: что делать, если игра не идёт

«Инструменты» → **«Журнал ядра»**.

Здесь три источника:

- **ядро** — файл, который эмулятор пишет во время запуска (последние 256 КБ, чтобы
  телефон не задохнулся: за долгий сеанс журнал бывает в сотни мегабайт);
- **прошлый запуск** — то, что ядро отложило в сторону при старте: именно этот файл нужен,
  если игра вылетела и приложение перезапустилось;
- **Symbiosis** — решения прослойки: какой драйвер выбран, какой режим, сколько памяти
  выделено;
- **сеансы** — журналы прошлых запусков: по одному файлу на запуск.

Кнопки: **Обновить**, **Копировать**, **Отправить**, **В «Загрузки»**.

Кнопки «Очистить» здесь больше нет и не будет: журнал — это улика, а не мусор. Если
сеанс закончился вылетом, именно его файл отвечает на вопрос «почему». Поэтому каждый
запуск сначала откладывает прошлый журнал в `sessions/`, а старые сеансы удаляются
ТОЛЬКО по лимиту (200 файлов или 200 МБ) и только самые старые. Кнопка «В «Загрузки»»
кладёт текущий журнал в `Download/Symbiosis/logs/` — оттуда его можно отправить кому
угодно, ничем не рискуя.

Что делать по шагам:

1. Запустите проблемную игру и доведите до момента, когда всё ломается.
2. Вернитесь (или откройте приложение заново после вылета) → «Журнал ядра».
3. Нажмите «Обновить». В строке состояния сразу видно число ошибок: `ошибок: 7`.
4. Ищите строки с `<Error>` и `<Critical>` — это они. Кнопка «Отправить» отдаёт журнал
   в почту или мессенджер, «Копировать» — в буфер.

Если журнал пуст, значит игра ещё ни разу не запускалась: ядро создаёт файл, когда
начинает писать. Экран в этом случае показывает папку, где файл появится.

## 14. Источники: любая ссылка → файлы → скачать или смотреть по частям

«Инструменты» → **«Источники»**.

Экран отвечает на один вопрос: «вот ссылка — что по ней лежит?». Вставьте адрес
(кнопка **«Вставить»** берёт его из буфера обмена) и нажмите **«Открыть»**.

### Что можно вставить

| Что | Что получится |
|---|---|
| Адрес открытого каталога (зеркало дистрибутива, архив, файлопомойка) | Список файлов и папок: имя, вид, размер |
| Прямая ссылка на файл | Одна карточка: имя, размер, «Скачать» / «По частям» |
| Ссылка на `.torrent` | Список файлов внутри торрента с размерами |
| `magnet:?xt=urn:btih:…` | То же, но список файлов сначала надо получить у пиров |

### Что делает каждая кнопка

- **Открыть** — читает страницу и разбирает ссылки. Относительные (`linux/ubuntu.iso`)
  приводятся к полным, служебные («Parent Directory», сортировка, меню сайта)
  отбрасываются.
- **Скачать** — качает файл в `Download/Symbiosis/Источники`, показывает проценты,
  мегабайты и скорость. Незаконченная загрузка докачивается с того же места, если
  сервер это умеет; если не умеет — начинается заново, чтобы файл не склеился из двух
  разных кусков.
- **По частям** — открывает видео или музыку, не скачивая целиком. Работает так:
  приложение поднимает маленький сервер на самом телефоне (127.0.0.1), плеер просит у
  него кусок, сервер идёт с этим диапазоном к источнику и отдаёт ровно его. Перемотка —
  это новый диапазон, а не новая загрузка.
- **Файлы** (у `.torrent` и magnet) — показать, что внутри, и выбрать: «Скачать всё» или
  один файл.

### Если сайт не отдаёт список

Экран пишет причину, а не «ничего не найдено»:

- `403` — открытый список закрыт (часто нужен ключ в адресе);
- `401` — нужен вход в аккаунт: откройте сайт в браузере и возьмите прямую ссылку;
- «страница собирается скриптами» — в тексте страницы нет ссылок, их рисует JavaScript;
- «адрес не найден» — проверьте интернет и имя сайта.

### Торренты: чего ждать честно

- Список файлов из `.torrent` виден сразу: он внутри файла.
- В magnet список файлов хранится НЕ в ссылке, а у пиров. Если в ссылке нет трекеров,
  искать негде — экран так и скажет.
- Скачивание идёт с пиров, которых выдал трекер. Мало раздающих — медленно; нет совсем —
  «никто не отдал ни одного куска». Это состояние торрента, а не сбой приложения.
- Каждый кусок проверяется по SHA-1: испорченный не попадёт в файл, он будет запрошен
  заново у другого пира.

### Где оказываются файлы

`Download/Symbiosis/Источники`. Это та же папка `Download/Symbiosis`, что у конвертера.
Чтобы скачанная игра появилась в библиотеке, добавьте эту папку в «Инструменты» →
«Папки игр» (кнопка «Папки игр» есть и прямо на экране «Источники»).

## 15. Кадры прыгают или звук трещит: экран «Ровность кадров»

«Инструменты» → **Ровность кадров**. Это не «оптимизация одной кнопкой», а замер:
поиграйте минуту там, где плохо, выйдите и откройте экран.

Сверху — четыре числа: **медиана**, **90%**, **худшие 1%** и **самый долгий кадр**.
Медиана говорит, как обычно идёт игра; худшие 1% — как часто бывают провалы;
худший кадр — насколько глубоко. Ниже — **причина**, названная по числам, и что с ней делать.

| Что видно | Что это значит | Что менять |
|---|---|---|
| 60 → 30 → 15, ровно в два раза | упор в вертикальную синхронизацию | Графика → VSync «Выкл» |
| медиана нормальная, но есть кадры в 5-10 раз дольше | сборка шейдеров в момент кадра | асинхронные шейдеры + пройти это место ещё раз |
| ровно, потом резко вдвое хуже | нагрев, сброс частот | дать остыть, снизить разрешение, турбо не помогает |
| картинка ровная, звук рвётся | буфер звука 10 мс | раздел «Звук» на том же экране: 20 или 30 мс |

**Звук.** Eden держит 240 сэмплов (5 мс), то есть 10 мс буфера. Если телефон не
забирает буфер вовремя, движок повторяет последний кадр — это и слышно как треск
и «заедание» эффектов. Чипы **10 / 20 / 30 / 50 мс** ставят `symbiosis_audio_buffer_ms`;
значение крупнее — надёжнее, но звук отстаёт от картинки, поэтому 30-50 мс — это
лечение, а не настройка по умолчанию. Действует после перезапуска игры.

Кнопка **«Скопировать отчёт»** кладёт числа и причину в буфер обмена — удобно
приложить к вопросу, вместо «лагает».

## 16. Если распаковка ничего не дала

В шторке теперь написана **причина**, а не только путь. Читать надо первую строку:

| Первая строка | Что это значит | Что делать |
|---|---|---|
| «это архив ZIP (RAR, 7z), а не образ» | выбран архив, внутри которого лежит образ | распаковать архив в проводнике и выбрать файл оттуда |
| «файл обрезан / слишком мал» | скачивание не завершилось | докачать файл |
| «это не сжатый образ» | внутри нет таблицы NSZ/XCZ/NCZ | проверить, тот ли файл выбран |
| «некуда распаковать» | нет места или папка недоступна | освободить место |
| «уже распакован» | .nsp/.xci/.nca/.nro | файл копируется как есть, открывать можно сразу |

Формат определяется по первым байтам файла, а не по расширению: переименованный
zip будет назван архивом, а не «битым образом». Результат — в `Download/Symbiosis`.

Если файл всё-таки не распаковался, рядом появляется `последняя-ошибка.txt`:
имя файла, размер, первые байты и дословный ответ ядра («Block 12 is damaged»,
«truncated»). По нему видно, повреждён файл или это ошибка распаковщика.

### «Распаковалось, но ядро файл не принимает»

Этого текста больше нет — вместо него причина. Проверка, которой Eden отсеивает
файлы при запуске, строже, чем «файл открывается»: внутри NSP должен найтись NCA
с программой игры, а ищет его ядро по служебному файлу `*.cnmt.nca`. Наша
диагностика проверяла только номер игры, проходила её и падала на этой —
в шторке оставалось «ядро не принимает этот файл», без единого слова о причине.

Теперь проверка та же, что у ядра, и звено называется:

| Написано в шторке | Что это значит | Что делать |
|---|---|---|
| «файла *.cnmt.nca нет» | контейнер собран без служебного файла | пересобрать из исходного `.nsz`; если повторяется — приложите `последняя-ошибка.txt` |
| «файл … меньше 0x204 байт» | внутри пусто — распаковка записала ничего | перекачайте и распакуйте заново |
| «CNMT и NCA на месте, оглавление целое… нет title key» | контейнер целый, но содержимое NCA не открывается | положите полный `prod.keys` (в нём должны быть title keys) |
| «Каждый NCA по отдельности: … MissingTitlekey» | ядро назвало NCA и точный статус | нужен title key этой игры |

Вместе с причиной в шторке перечислены **все** файлы внутри контейнера и их
размеры: по этому списку видно, что распаковалось, а что осталось сжатым.
Полный текст лежит рядом с результатом в `почему-не-открывается.txt` — его
можно переслать целиком.

**Чего проверка НЕ делает.** Она не ищет метку `NCA3` в открытых байтах: её там
нет. Ядро сначала расшифровывает заголовок NCA ключом, и только потом сверяет
метку — поэтому «метки нет» ничего не говорит о распаковке. Первая версия
проверки этого не знала и зря обвиняла распаковку.

---


### «Сжатые данные внутри файла повреждены»

Это сообщение значит меньше, чем кажется. Оно появлялось, когда распаковщик
видел блок, который распаковался не ровно на свой полный размер. Проверка была
наша, а не zstd: сжатие тут ни при чём, библиотека распаковывала блок без
единой жалобы — просто содержимое блока оказывалось короче.

Теперь так: короткий блок принимается, а решение принимает **размер файла,
записанный в самом заголовке NCA**. Если распакованное кончается ровно на нём
— файл целый, что бы ни заявляла таблица. Если не совпало — отказ, в котором
написано, на каком байте кончились данные и сколько обещала таблица.

Что делать, если сообщение всё-таки появилось: перекачайте файл. Теперь эта
фраза означает именно нехватку данных, а не «нам не понравился размер блока».

## 17. Если второе ядро не запускается

Окно «Почему не запустилось» теперь показывает **отчёт**, а не догадку:

- **шаг** — где оборвалось: `dlopen` (файл ядра), `javaInitialize` (передача
  путей), `deviceInitialize`, `graphicsInitialize`;
- **сигнал** и **адрес** — например `SIGSEGV`, `0x0`;
- **верхние кадры** — `libkenji.so+0x1a2b3` значит «внутри файла ядра»,
  `libsymbiosis_kenji.so+…` — «внутри моста приложения»;
- **debug_break** — ядро само сообщило об ошибке инициализации.

Отчёт пишется до падения процесса, поэтому он есть даже тогда, когда процесс
уже умер. Кнопка «Скопировать» кладёт его в буфер — приложите к вопросу.

Если в отчёте **SIGABRT** — это не сбой памяти: программа сама остановилась
(у .NET-ядер так заканчивается необработанное исключение). Приложение тогда
дополнительно читает журнал системы и показывает строки про исключение — по ним
видно, чего ядру не хватило.

### Что именно показывает окно падения

Порядок разделов — от самого прямого к самому косвенному:

1. **Отчёт о падении** — шаг, сигнал, адрес, кадры (файл `kenji-crash.txt`).
2. **Что сказало ядро перед остановкой** — его собственный вывод дословно
   (`kenji-stdout.txt`). Если ни одна строка не похожа на знакомое
   `Unhandled exception`, показываются просто последние строки: раньше в этом
   случае окно говорило «ядро ничего не написало», хотя текст был.
3. **Что записала система** — причина от Android и снимок аварийного
   завершения (tombstone). В нём есть строка `Abort message:` — это ровно тот
   текст, с которым процесс сам себя остановил, — и кадры, уже подписанные
   именами функций. Снимок сохраняется рядом как `kenji-exit.txt`.
4. **Что ядро спрашивало у Java** — дословные `FindClass`, `GetMethodID` и
   отметки «в очереди исключение» из `kenji-jni.txt`. Ядро умирает молча
   чаще всего потому, что спросило класс, получило пустой ответ и не
   проверило его; эта строка называет класс.
5. **Хвост журнала процесса** — последние строки без всякого отбора.

Все пять файлов лежат в одной папке: `Android/data/<пакет>/files/symbiosis/`.
Любой из них можно отправить как есть — распознавать в них ничего не нужно.
Если отчёта нет вовсе, процесс остановила система (обычно из-за памяти):
тогда смотрите «Журнал ядра» и «Диагностику».

Отдельно про **«Журнал ядра»**: если файл создан, но пуст (`eden_log.txt · 0 КБ`),
это не «сломалось» — свой файловый журнал ядро включает отдельно. Переключитесь
на источник **«система»**: системный журнал пишется всегда и содержит те же
строки о запуске и падениях.

## 18. Быстрые настройки в игре: что меняется сразу, а что после перезапуска

Панель (меню в игре → «Быстрые настройки») теперь не десять пунктов, а полный
набор того, что реально влияет на игру:

| Пункт | Когда подействует |
|---|---|
| Громкость | **сразу** |
| Предел кадров, турбо/медленный режим | **сразу** |
| Разрешение | после перезапуска игры |
| Вертикальная синхронизация | после перезапуска |
| Точность GPU, фильтр масштабирования, сглаживание | после перезапуска |
| Звуковой движок (Oboe / Cubeb / OpenSL) | после перезапуска |
| Буфер звука 10 / 20 / 30 / 50 мс | после перезапуска |

Под каждым пунктом написано, к какой из двух колонок он относится, а внизу
появляется кнопка **«Перезапустить игру»** — она сохраняет настройки и
перезапускает игру с ними, чтобы не искать, как это сделать вручную.

Почему так, а не «всё сразу»: разрешение ядро пересчитывает при инициализации
видео, звуковой движок создаётся один раз при старте звука. Иначе это не
работает — не потому, что настройка не применилась, а потому что её никто не
перечитал.

**Если звук трещит.** Буфер 10 мс — значение Eden по умолчанию; в тяжёлых
сценах телефон не забирает буфер вовремя, и движок повторяет последний кадр
(это и слышно). Поставьте 20 мс, перезапустите игру; если треск остался — 30.

**Если что-то всё-таки упало, причина будет на экране.** При следующем
запуске игры приложение показывает диалог «Прошлый запуск остановился»: сигнал
(для сбоя внутри эмуляции) или тип ошибки (для ошибки в коде приложения), шаг —
что именно делали, например «настройки: громкость», — и несколько кадров стека.
Кнопка «Скопировать» кладёт весь текст в буфер. Раньше на этом месте была
только надпись в шторке «Приложение остановлено».

**Панель больше не роняет игру.** Раньше на каждое изменение панель
пересобиралась целиком — из обработчика того самого пункта, который в этот
момент убирали с экрана. Android такого не прощает: приложение закрывалось
сразу после нажатия. Теперь меняются только подписи и подсветка выбранного
значения, а кнопка «Перезапустить игру» просто показывается, когда нужна.
Если же приложение всё-таки закроется — причина останется в файле
`symbiosis/ui-crash.txt` во внешней папке приложения (время, поток, тип
ошибки, стек), а не только в надписи «приложение остановлено».

## Быстрая проверка: если что-то не так

Проверяйте сверху вниз, пока не найдётся причина. Каждый пункт — один экран.

1. **Список пуст.** «Папки» → добавить папку. Если папка уже есть — потяните список вниз:
   это повторный обход.
2. **Игра не запускается.** Нажмите плитку: причина будет в диалоге. Чаще всего — нет
   ключей или образ сжатый.
3. **Чёрный экран или вылет.** «Инструменты» → «Журнал ядра» (раздел 13): что сказало
   ядро в этом и прошлом запуске. Плюс «Диагностика» → отчёт о запуске.
4. **Одна игра идёт, другая нет.** Долгое нажатие на плитке → «Запустить на Kenji-NX».
   Игра, которая не идёт на одном ядре, иногда идёт на другом.
5. **Нужен файл из интернета.** «Инструменты» → «Источники» (раздел 14): вставить ссылку,
   скачать или открыть по частям.

## 28. Звук и ключи: что делать руками

### 28.1. Хрип в музыке

Панель быстрых настроек → **Частота звука**. Три варианта:

| Вариант | Когда выбирать |
|---|---|
| **авто** (по умолчанию) | почти всегда: телефон открывает поток на своей родной частоте, пересчитывать нечего |
| **48000 Гц** | если телефон сам на 48 кГц, а авто почему-то даёт 44,1 |
| **44100 Гц** | если авто выдаёт 48, а телефон живёт на 44,1 |

Под кнопками — строка **«Сейчас: …»**. Это замер с работающего потока, а не
подпись: там видно, какую частоту попросили, какую дал телефон, сколько
кадров в буфере и сколько было опустошений (каждое слышно как щелчок).

Что означает строка:

- «просили 48000 Гц, телефон дал 44100 Гц … пересчитывается» — настройка
  дошла, но частота не совпала: ставьте **авто** или **44100**;
- «Опустошений буфера: 37 — каждое слышно как щелчок» — увеличьте **Буфер
  звука** до 30 мс;
- «Опустошений буфера нет — если хрип слышен, причина не в буфере» — звук
  хрипит не из-за звукового слоя: смотрите нагрузку (разрешение, режим).

Замер обновляется после перезапуска игры: поток открывается при старте.

### 28.2. Игра просит ключ, которого нет

Папка `keys` в данных приложения может содержать **несколько** файлов ключей:
`prod.keys`, `title.keys`, `console.keys` и файл ключа отдельной игры.
Все они применяются **перед каждым запуском** — специально для NSP, который
жалуется на отсутствующий ключ, пока другие игры на тех же ключах работают.

Экран «Ключи и прошивка» → кнопка установки принимает любой файл ключей и
сохраняет его под исходным именем; кнопка **«Перечитать ключи»** применяет
всё, что лежит в папке, не выходя из экрана. Отчёт на том же экране называет,
какие файлы подхвачены, сколько ключей добавлено и сколько строк не разобрано.

Существующие ключи при этом не перезаписываются: если в основном
`prod.keys` ключ уже есть, дополнительный файл его не тронет.

### 28.3. Если снова «Ядро не запустилось»

В окне отчёта теперь есть строка **«перехват abort: …»**. По ней видно, какая
защита сработала:

- «подменено слотов: 1» — виновник назван ниже строкой `abort() позвал кадр`;
  присылайте отчёт целиком;
- «не взведён» — перехват не встал, и отчёт о причине ничего не говорит;
  присылайте эти строки, ничего не меняя.
